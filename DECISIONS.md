# Decisions log

One line per decision: what and why.

- 2026-10-21 — Local dev without Docker uses the system Postgres 16 (role/db `halo`, plus `halo_test`); `docker-compose.yml` remains the documented path. Container here has no Docker daemon.
- 2026-10-21 — Pinned to versions I can vouch for instead of bleeding-edge majors: Next 15.5, React 19.2, TS 5.9, TanStack Table 8, ESLint 9, Vitest 3, zod 3.25, motion 12, lucide 0.577. Spec says Next 15; newer majors (TS 7, Table 9) add risk without value.
- 2026-10-21 — `@playwright/test` pinned to 1.56.1 because the preinstalled Chromium is revision 1194.
- 2026-10-21 — Fonts via `@fontsource-variable/inter` / `jetbrains-mono` instead of `next/font/google` so builds work offline.
- 2026-10-21 — shadcn registry is unreachable from this environment; shadcn/ui primitives are written by hand (same source shape, `radix-ui` unified package) and `components.json` kept for future `shadcn add`.
- 2026-10-21 — Web calls the API directly at `NEXT_PUBLIC_API_URL` with `credentials: "include"`; CORS allows the web origin. localhost:3000 and :8000 are same-site, so the SameSite=Lax httpOnly cookie works and SSE is not buffered by a proxy.
- 2026-10-21 — `make types` exports OpenAPI from the app object (`python -m app.openapi_export`) so it does not need a running server.
- 2026-10-21 — Added columns beyond Section 5 where the UI needs them: `deals.stage_entered_at` (days-in-stage), `tasks.completed_at`, `notes.created_by` (agent badge on notes).
- 2026-10-21 — Interactions (emails/calls/meetings) are logged against the *contact* with `payload.deal_id` when they concern a deal; stage changes/notes go on the deal. Timelines union related records (contact ← its deals; deal ← activities tagged with it; company ← its contacts and deals).
- 2026-10-21 — `deals.stage_id` FK uses NO ACTION (not RESTRICT) so deleting a workspace cascades cleanly; the stage service refuses to delete a stage that still has deals.
- 2026-10-21 — Session dependency uses `Depends(..., scope="function")` so the commit lands before the response is sent (FastAPI's default runs yield-teardown after sending).
- 2026-10-21 — Scoring windows: replied = email_received ≤14d; meeting = meeting ≤14d ago or scheduled in the future; opened_multiple = email_sent ≤30d with opens ≥2; stale = no interaction ≤14d. Max achievable score is 90 by design (sum of positive weights).
- 2026-10-21 — Seed uses a seeded `random.Random` for ids too (uuid from rng bits), and fixed uuid5 ids for the demo user/workspace, so `make seed`/`POST /demo/reset` are idempotent and existing sessions survive a reset. Dates are relative to "now".
- 2026-10-21 — The demo workspace gets 3 teammates (Maya, Jonas, Priya @halo.dev, same password) so owners/avatars/filters look real.
- 2026-10-21 — Industry templates are Python dataclasses (`onboarding/templates/*.py`) with curated company names per industry instead of Faker company names (Faker's read as fake).
- 2026-10-21 — Tests run against `halo_test`: the schema is rebuilt with `alembic upgrade head` at session start (validates migrations), the demo seed is loaded once, and each test runs in an outer transaction rolled back at the end (`join_transaction_mode="create_savepoint"`).
- 2026-10-21 — List pagination uses an opaque offset cursor (`next_cursor` = next offset); simple, works with any sort, and lists are small (≤ 500 per page).
- 2026-10-21 — `filter` is validated by a per-object Pydantic model with `extra="forbid"`; custom-field filters use JSONB containment (`custom @> {...}`), which handles selects and multi-selects alike.
- 2026-10-21 — Deal moves take a target `index` in the column; the server computes a float position between neighbours, so clients and the agent never compute positions.
- 2026-10-21 — Added `GET /pipelines/{id}/board` (stages + totals + deals in one call) for the kanban; `/deals` list remains for tables.
- 2026-10-21 — Response models set `json_schema_serialization_defaults_required` so generated TS types mark always-present fields as required; money uses a `Money` type that always serializes as a 2-decimal string.
- 2026-10-21 — Table/record UI is driven by "field descriptors": system columns are declared once per object in `lib/records/descriptors.ts` and custom fields are appended from `/fields`, so FieldRenderer/FieldEditor are shared by tables and detail panels.
- 2026-10-21 — Table view state (view tab, search, sort, ad-hoc filter) lives in the URL. Saved views are code-defined presets (All/Mine/Hot/Stale…) rather than persisted server objects — enough for the MVP and lets the agent's `apply_filter`/`navigate` drive tables.
- 2026-10-21 — Inline edits open a small popover editor anchored to the cell (Attio-style) instead of swapping the cell for an input, to avoid row height jumps; clicking the name cell opens the record.
- 2026-10-21 — openapi-typescript runs with `--default-non-nullable false` so request fields with server defaults stay optional in TS.
- 2026-10-21 — No row virtualization yet; tables render up to 500 rows per page. Revisit in Phase 9 if 500-row scrolling isn't smooth.
- 2026-10-21 — Kanban cards have two layers: an outer `motion.div` (layout/layoutId for animated cross-column moves) and an inner dnd-kit sortable node; layout animation is disabled while dragging and for 250 ms after drop so the two systems never fight.
- 2026-10-21 — Today's "Due today" shows the signed-in user's tasks; the contact queue is workspace-wide (top 8 by score).
- 2026-10-21 — Today's stage chart is a single-series HTML bar list (one hue, value at the tip, tooltip) rather than recharts — better typography for 5–7 bars; recharts is used for the agent's chart card.
- 2026-10-21 — Playwright global setup resets the demo workspace (`POST /demo/reset`) so e2e runs are deterministic; tests clean up the fields/stages they add.
- 2026-10-21 — Event protocol extensions: `message_start.conversation_id`, `message_end.suggestions` (clickable prompts) and card kind `next_step` (one-click "Create task" from a summary). Everything else matches Section 6.2.
- 2026-10-21 — Plans are stored as data (steps with tool + args + before/after ui_actions, prelude, finale, summary). Execution is provider-agnostic, so a real LLM provider reuses the same executor.
- 2026-10-21 — Orchestrator commits after every tool call so `invalidate` ui_actions refetch committed data; a provider asking for a mutating tool outside an approved plan gets a failed tool_result instead.
- 2026-10-21 — Exact undo: `services.activities.collect_activities()` records ids of activities written during a tool run; tools snapshot affected rows (deal stage/position/timestamps, record fields) and restore them; scores are recomputed afterwards.
- 2026-10-21 — `search_records` also searches tasks (`object_type: task`, buckets, `mine`) because S1 needs tasks and the Section 6.4 tool list has no task reader; contact results include top score reasons.
- 2026-10-21 — The briefing exists as JSON (`GET /agent/briefing`) and as an unsaved SSE stream (`GET /agent/briefing/stream`) that runs the S1 scenario without creating a conversation; Today uses the stream.
- 2026-10-21 — Mock "intelligence" (insights, next steps, drafts) is rule-based over real data in `agent/insights.py` / `agent/drafting.py`; it is shared by tools, `/agent/insights` and scenarios.
- 2026-10-21 — Card payloads have Pydantic models (`agent/cards.py`) exposed via `GET /agent/cards/schema`, so the web renders cards from generated types instead of hand-written ones.
- 2026-10-21 — The SSE client retries only when the connection fails before the first event (safe to resend); mid-stream drops surface as an error event.
- 2026-10-21 — The executor uses its own reveal-scrolling (vertical centring; horizontal only when the target fits) instead of `scrollIntoView`, which over-scrolled wide tables and the kanban; highlight rings are clipped to `#main` so they never spill under the panel.
- 2026-10-21 — `move_card` is applied to the cached board (same `applyMove` as drag & drop) so motion's `layoutId` animates the card between columns; the server refetch that follows confirms the persisted position.
- 2026-10-21 — "Save as note" and "Create task" on agent cards are direct user actions (REST), not agent mutations, so they don't need a plan; agent-proposed changes always go through plans.
- 2026-10-21 — Pages that sit beside the agent panel (Today, record detail, table toolbars) use container queries rather than viewport breakpoints.
- 2026-10-21 — Onboarding builds the whole workspace in one transaction and commits only at the end: a dropped connection leaves the workspace pending and onboarding can simply be retried. A `SELECT … FOR UPDATE` on the workspace row serialises concurrent runs.
- 2026-10-21 — Template matching: keywords match on word boundaries; multi-word phrases score per word; ties go to the template whose first match appears earliest in the sentence (usually its subject — "a recruitment agency placing software engineers" → recruitment).
- 2026-10-21 — Onboarding events are their own typed union (`onboarding/events.py`, exposed via `GET /onboarding/events/schema`); `done` step events carry preview data (terminology, stages, fields, counts, sample names, sample deals) so the frontend skeleton never needs extra requests.
- 2026-10-21 — "Skip, use demo workspace" fills the new user's own workspace from the B2B template instantly (`POST /onboarding/demo`) instead of sharing the global demo workspace, so their data is theirs to change.
- 2026-10-21 — New workspaces are seeded from `workspace_id.int` so seeded ids never collide across workspaces; sample teammates get `team-<id>.example.com` emails and an unusable password hash.
- 2026-10-21 — The seed builder only draws a unit number when a deal pattern uses `{unit}`, so adding real-estate patterns didn't shift the demo workspace's deterministic data.
- 2026-10-21 — The SSE client is generic (`streamSSE<E>`), shared by the agent and onboarding streams.
- 2026-10-21 — "Last activity" for companies/contacts is computed with one indexed aggregate per related type (company + its contacts; contact + their deals) merged in Python. The previous single query joined activities with `OR` conditions, which Postgres can't index: 500 contacts took 6 s, now ~50 ms.
- 2026-10-21 — Large tables render progressively (60 rows at once, then 120-row chunks in `startTransition`, with a spacer row keeping the scrollbar stable) instead of adding a virtualization dependency. Rows are memoized and column definitions read callbacks through refs, so selecting or editing a row re-renders only that row.
- 2026-10-21 — Inline-edit popovers mount only while a cell is being edited (anchored through Radix `virtualRef`), so a 500-row table doesn't create ~4 000 idle Popper instances.
- 2026-10-21 — The hot-lead threshold lives in one place per side (`services.scoring.HOT_SCORE`, `lib/records/views.HOT_SCORE`); onboarding no longer imports from agent scenarios (that import was circular).
- 2026-10-21 — Added `@axe-core/playwright` (dev-only) for an automated WCAG 2.1 A/AA audit of every main screen, the AI panel, ⌘K and onboarding in e2e. Not in the Section 3 list; it never ships to users.
- 2026-10-21 — Light-mode `--muted-foreground` moved from zinc-500 (#71717a, 4.39:1 on muted surfaces) to #68686f (≥ 5:1); small rose status text uses rose-700. Visually near-identical, now AA everywhere.
- 2026-10-21 — Inline editors and links are siblings, never nested: an editable email/url/company/contact cell renders plain text inside the editor trigger plus a small "open" link button that appears on hover/focus.
- 2026-10-21 — `openai_compat.py` (optional Phase 8 item) exposes read-only tools as functions and mutating tools only through a `propose_plan` function. Proposed steps are validated with the tools' own Pydantic args and become the same stored plan the mock produces, so approval, watchable execution and exact undo don't depend on the model behaving. Tested against a scripted fake server (`httpx.MockTransport`, streamed SSE with split tool-call arguments).
- 2026-10-21 — `httpx` moved from dev-only to a runtime dependency of the API (used by the OpenAI-compatible provider); still listed in Section 3 for tests.
